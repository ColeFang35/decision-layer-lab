# decision-layer-lab · 置信度校准实验台

**问一个问题：模型自己报的置信度，能不能拿来设阈值？**

现在做 Agent 的普遍做法是让大模型输出一个 JSON，带上它自报的 confidence，
然后拿这个数去分流（低置信度转人工）。**但这个数字很少被检验过。**

本实验在两类真实的分类任务上，把「规则 / 生成模型」放在一起，
用 **ECE、可靠性图、弃权曲线、AURC** 去量它们的置信度到底可不可信。

## 这条线里的位置

做 Agent 的过程中被同一类问题绊了几次，就各做了一个小实验：**这一步是真的对了，还是只是看起来对了。**

- [rag-lab](https://github.com/ColeFang35/rag-lab) —— 检索方案哪个更好，重排值不值那个延迟
- [llm-judge-eval](https://github.com/ColeFang35/llm-judge-eval) —— 用 LLM 当裁判，裁判自己可不可信
- **decision-layer-lab**（本仓库）—— 模型自报的置信度能不能拿来设阈值

## 结论先说

数据集：任务 A 客服工单分诊（50 条易档 + 33 条难档），任务 B 知识路由（48 条 query）。
模型：`deepseek-flash` / `deepseek-v4-pro`。成本合计 **$0.082**。

| 任务 | 档 | 方案 | 准确率 | 平均置信度 | ECE ↓ | AURC ↓ |
|---|---|---|---|---|---|---|
| A 分诊 | 易 | deepseek-flash | 100.0% | 0.949 | 0.051 | 0.000 |
| A 分诊 | 易 | deepseek-v4-pro | 96.0% | 0.958 | 0.002 | 0.002 |
| A 分诊 | 易 | rule | 84.0% | 0.928 | 0.088 | 0.086 |
| A 分诊 | **难** | deepseek-flash | 93.9% | 0.831 | **0.108** | 0.019 |
| A 分诊 | **难** | deepseek-v4-pro | 93.9% | 0.862 | **0.090** | 0.036 |
| A 分诊 | **难** | rule | **27.3%** | 0.264 | **0.009** ⚠️ | **0.380** |
| B 路由 | 带描述 | deepseek-flash | 95.8% | 0.967 | 0.009 | 0.009 |
| B 路由 | **只给标题** | deepseek-flash | 93.8% | 0.958 | 0.020 | 0.021 |
| B 路由 | **只给标题** | deepseek-v4-pro | 93.8% | 0.961 | 0.023 | 0.024 |
| B 路由 | 只给标题 | rule | 72.9% | 0.521 | 0.209 | 0.098 |

### 1. 低 ECE 不代表能用 —— 这是本实验最该记住的一条

看难档那一行：**规则的 ECE = 0.009，全场最好看**。但它的准确率只有 **27.3%**。

它"校准"是因为**它知道自己不行**：置信度也跟着掉到了 0.264，所以两者对上了。
而它的 **AURC = 0.380 是全场最差** —— 意味着「低置信度转人工」这个策略在它身上
**救不回来**：它能答对的 27% 和答错的 73%，在置信度上根本分不开。

> **校准指标必须和准确率一起看。** 单看 ECE 会被"模型清楚自己不行"这种假象骗过去。

### 2. 「LLM 自报置信度过度自信」——在这个实验里不成立

我原本的假设正是这一条，**结果被证伪了**。

即便在难档（消息里**一个类名关键词都没有**，必须靠语义推断），两个 DeepSeek 模型
依然是**偏保守**的：准确率 93.9%，自报置信度只有 0.831 / 0.862。**它们说的是少了，不是多了。**

可靠性图上也看得出来：点紧贴对角线，没有系统性落在下方。

> "LLM 过度自信"是个流行说法，但**至少对这两个模型、这两类任务，它不成立**。
> 有意思的是，**"过度自信"这个毛病出现在规则方案身上**（见上面的可靠性图）。

### 3. 但校准确实随难度退化

ECE：`flash` 0.051 → **0.108**，`v4-pro` 0.002 → **0.090**。
可靠性图上，难档的点明显比易档散、偏离对角线更多。

**这条是第一轮实验测不出来的** —— 第一版任务出得太送分（flash 拿到 100% 准确率），
**准确率太高的时候校准必然看起来完美**，没有错题可以暴露问题。
加上难度对照，才看到这条退化曲线。

## 为什么是「弃权曲线」而不是准确率

准确率高不代表能用。真实业务里没人会让模型硬答所有题，低置信度的应该转人工。

所以关键指标是：**允许模型跳过自己最不确定的那批样本时，剩下的准确率怎么变。**

- 校准好的模型：弃权 20% 就能换来明显更高的准确率，曲线陡
- 置信度不可用的模型：曲线是平的，因为它"心虚"和"有把握"的样本分不开

**一个模型能不能用置信度做路由，看这一张图就够了。** 单看准确率看不出区别。

## 两个任务，各有难度对照

**任务 A · 客服工单分诊**（`run_triage.py easy|hard`）—— 复刻官方 `patterns/intent-routing`：
一次调用并行问三个原子问题（意图 / 紧急度 / 复杂度），再按置信度分流到
确定性代码、专家 LLM 或人工。

- **easy**：50 条消息里直接带类名关键词（"发票""退款"），靠关键词就能分对
- **hard**：33 条**刻意改成间接表述，类名关键词零出现**（已用脚本校验），必须靠语义推断。
  比如「钱什么时候能回来」→ 退款到账、「扣了我两次」→ 支付问题

**任务 B · 知识路由**（`run_routing.py desc|bare`）—— 把用户问法路由到 16 条知识中正确的一条。

- **desc**：每个选项带一句从知识正文摘的说明 —— 这一档其实偏简单
- **bare**：只给标题、不给任何说明。这才是真实场景

语料复用姊妹项目 [`rag-lab`](https://github.com/ColeFang35/rag-lab) 的真实知识库。

## 快速开始

```bash
pip install -r requirements.txt
cp .env.example .env        # 填 key；不填也能跑（自动走 mock）

python run_triage.py easy
python run_triage.py hard
python run_routing.py desc
python run_routing.py bare
```

跑完在 `results/<任务>-<档>/` 下得到 `report.md`、`abstention.svg`、`reliability.svg`、`rows.json`。

### 没有 key 也能跑

没配 key 时自动用 `MockProvider`（两个 profile：一个按构造校准、一个过度自信），
**所有输出都会显式标注是假数据**，用来验证指标算得对不对、图画得通不通。
这跟客服项目里的 ScriptedMockModel 是一个思路。**报告里会回显实际用了哪些 provider**，
避免"以为在跑真模型、其实跑的是 mock"。

### 需要配的东西

| 变量 | 用途 |
|---|---|
| `OPENAI_API_KEY` + `OPENAI_BASE_URL` | DeepSeek 兼容 OpenAI 协议、国内直连。去 https://platform.deepseek.com 建 key |
| `OPENAI_MODELS` | 一次跑多个模型做对照，逗号分隔 |
| `LLM_THINKING` | `enabled` / `disabled`。DeepSeek **默认开着 thinking**，关掉省大量输出 token |
| `MODEL_PRICES` | 单价覆盖，格式 `模型:输入价:输出价,...`。内置表在 `dlayer/prices.py`（**标注了取数日期**），查不到记 0 —— 别拿 0 当结论 |

## 几个实现上的坑（都是真踩过的）

**macOS 上 Python 的 urllib 会自动走系统代理。** 即使环境变量里 `HTTP_PROXY` 是空的，
`urllib.request.getproxies()` 也会返回系统代理。后果是**同一个请求 curl 走直连、
Python 走代理** —— 实测卡死 13 分钟、CPU 累计只用 1.18 秒。`dlayer/http.py` 里显式关掉了。

**置信度没有区分度的方案，不画进弃权曲线。** 规则的置信度是「命中 1.0、兜底 1/n」，
排序等于随机，AURC 会显得很漂亮但完全是假象。代码里会判定并剔除、报告单独说明。

**结果先落 `raw.json` 再生成报告。** 第一次跑完因为报告渲染的 bug，14 分钟的 API 数据全丢了。

**分箱数随样本量自适应**（`n // 8`，下限 3 箱）。几十个样本分 10 箱，可靠性图全是噪声。

**不依赖 matplotlib**，两张图是纯 Python 拼的 SVG。

## 已知的边界

- 样本量小（33~50 条），结论是**方法层面**的，具体百分比不要外推
- 任务 A 的语料**人工构造**，难档的标注由作者判定
- **弃权曲线没出现戏剧性对比** —— 两个模型准确率都还在 93% 以上，没什么可弃权的。
  要让这张图真正拉开，任务得再难一档（准确率压到 70% 左右）
- **任务 B 的难度设计没起作用** —— desc 和 bare 只差 2 个点，标题本身信息量就够
- 只覆盖分类/路由这一类决策，没碰抽取、生成、多步推理
